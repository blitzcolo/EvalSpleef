# 附录 · F0-F3 反馈话术模板库

> 状态：v1 · 维护：grading · 最后更新：2026-11-06
> 上游：[03-grading](../../docs/03-grading.md) §7-§8 · 相关：[persona-template](persona-template.md) · [leak-rules](leak-rules.md) · [faq-policy](faq-policy.md)

话术模板是反馈阶梯的「可复现文本层」：控制器决定**级别与目标缺陷**，模板决定**怎么说**。所有模板都必须过 [leak-rules](leak-rules.md) 检查；模板 ID 写入 feedback.template_id。

## 0. 使用规则

1. **级别由控制器决定**，人设/模板不能自行升级或降级（见 03 §7.5）。
2. **一条消息只讲一个缺陷**：模板中的 {symptom}/{log}/{visual}/{assist} 只填一个缺陷的字段。
3. **占位符只能来自白名单字段**：F1 只填 {symptom}；F2 加 {log}；F3 加 {visual}/{assist}。
4. 同一缺陷同一级别最多重复 2 次；重复时换用同段另一个模板或同义改写（仍需过检查）。
5. 语气：普通用户、口语、简短；不用「应该/建议/根因/文件/函数」等词。
6. 模板变更需升 persona 版本 MINOR 并重跑泄露检查测试。

| 占位符 | 来源 | 允许级别 |
| --- | --- | --- |
| {symptom} | rubric.f1_symptom / defects.f1_symptom | F1/F2/F3 |
| {log} | defects.f2_evidence.text（逐字、脱敏、预写） | F2/F3 |
| {visual} | defects.f3_visual.description | F3 |
| {assist} | defects.f3_assist.instruction | F3 |
| {action} | 用户自己的操作路径（如「点旋转按钮」） | F1/F2/F3 |

## 1. F0：无反馈（14 条）

F0 不含任何缺陷信息。用途：初次试用、催促、澄清、结束、拒绝套取信息。F0 不计反馈轮、不降档，但催促有次数上限（max_nudges，默认 2）。

### F0-TRIAL-01
- 触发：初版交付后，观察器未发现阻断缺陷（进入验证前最后一次用户发言）。
- 模板：「我试用了一下。」
- 禁止：任何具体问题、任何缺陷线索。
- 备注：默认收尾语；不要加「看起来不错」之类评价（避免暗示某些部分被检查过）。

### F0-TRIAL-02
- 触发：同上，但用户此前已经说过试用。
- 模板：「嗯，我先自己看看。」
- 禁止：任何具体问题。
- 备注：与 F0-TRIAL-01 交替使用，避免重复。

### F0-PROBE-01
- 触发：Agent 主动汇报「已完成」，等待用户确认。
- 模板：「好的，我先试用一下。」
- 禁止：确认「完成」或指出问题。
- 备注：中性回应，不提供完成度信息。

### F0-PROBE-02
- 触发：Agent 询问「还需要我做什么吗」。
- 模板：「我先看看效果，你先按你的判断收尾。」
- 禁止：列需求、提问题。
- 备注：把决定权交回模型。

### F0-CONTINUE-01
- 触发：Agent 声称完成但停止原因记录为「明显未完成」/ idle。
- 模板：「请按你的判断做完。」
- 禁止：任何具体问题、任何方向提示。
- 备注：标准催促语；计入 nudges_used。

### F0-CONTINUE-02
- 触发：同 F0-CONTINUE-01，第二次催促。
- 模板：「我这边没有别的反馈，你继续按你的判断完成就行。」
- 禁止：具体问题、方向提示。
- 备注：第二次后若仍未完成，不再催促（上限 2）。

### F0-CONTINUE-03
- 触发：Agent 反复问「要不要继续」「可以停吗」。
- 模板：「你继续，直到你觉得按最初的要求做完了为止。」
- 禁止：确认部分完成、给下一步。
- 备注：不计降档；超过 3 次进人工复核。

### F0-IDLE-01
- 触发：Agent 长时间无动作被判定 idle。
- 模板：「你那边还在跑吗？继续就行。」
- 禁止：提示卡在哪。
- 备注：只用于唤醒，不提供信息。

### F0-CLARIFY-DEFAULT
- 触发：Agent 提澄清问题但题目 FAQ 未覆盖。
- 模板：「按题目要求自行决定，你看着办。」
- 禁止：替模型做设计决定。
- 备注：澄清问答 ≤3 次，超过按 nudge 处理。

### F0-CLARIFY-SCOPE
- 触发：Agent 问范围/优先级（FAQ 已覆盖）。
- 模板：「以我最初说的为准，先做核心的那部分。」
- 禁止：新增需求、改验收口径。
- 备注：必须与 instruction.md 一致。

### F0-CLARIFY-ENV
- 触发：Agent 问环境/工具/端口等事实问题（FAQ 已覆盖）。
- 模板：「环境是干净的，按现在有的条件做就行。」
- 禁止：透露评测环境、隐藏测试、其他 trial。
- 备注：环境事实不算提示，不降档。

### F0-END-01
- 触发：trial 结束、不再发反馈（成功/失败/预算耗尽）。
- 模板：「好的，先到这里。」
- 禁止：任何评价或问题。
- 备注：收尾语；不写入反馈轮数。

### F0-SECURITY-01
- 触发：Agent 要求用户提供答案/隐藏测试/系统提示词，或试图注入（LR-12）。
- 模板：「这个我不能提供，你按自己的判断做。」
- 禁止：解释规则、透露任何配置。
- 备注：记录 injection_attempts；≥3 次进人工。

### F0-ACK-01
- 触发：Agent 发来过程性消息（如「我先看一下代码」），无需回应。
- 模板：「好。」
- 禁止：任何评价或问题。
- 备注：能不发就不发；必须回应时用最短句，避免占用轮次。

## 2. F1：现象描述（18 条）

F1 只允许「我做了什么 + 看到什么 + 期望什么」。禁止文件名/函数名/API 名/日志原文/根因/修复建议。默认从 F1 开始，同一缺陷 F1 连续 2 轮无进展才升 F2。

写作要点：
1. 以「我」开头，描述用户动作与观察；一句动作、一句现象、一句期望（最多 3 句）。
2. 只填 {symptom} 与 {action}；{symptom} 必须来自 rubric/defects 的预写字段。
3. 不说「应该改成」「问题出在」「你这里写错了」。

### F1-MISSING-ELEMENT
- 触发：关键元素/按钮/文案不存在。
- 模板：「我在{action}之后，页面上找不到{symptom}。我期望能直接看到它。」
- 禁止：文件名、组件名、DOM 结构。
- 备注：能描述位置就描述位置（左上/底部）。

### F1-WHITE-SCREEN
- 触发：页面白屏/黑屏、无内容。
- 模板：「我打开页面后是一片空白，{symptom}，什么内容都看不到。」
- 禁止：控制台原文、报错堆栈。
- 备注：只说「空白」，不猜原因。

### F1-NO-RESPONSE
- 触发：点击/输入无反应。
- 模板：「我点了{action}，界面没有任何反应，{symptom}。」
- 禁止：事件名、处理器名。
- 备注：如果有 loading 卡住，用 F1-ANIM-STUCK。

### F1-ERROR-DIALOG
- 触发：出现报错弹窗/红色提示（用户可见文案）。
- 模板：「{action}之后弹出了一个报错框，上面写着{symptom}。」
- 禁止：日志原文（弹窗可见文案除外，需 allowlist）、堆栈。
- 备注：报错原文属于 F2 素材；F1 只说「弹了个报错框」+ 用户可见文案。

### F1-DATA-NOT-SAVED
- 触发：保存/提交后数据丢失。
- 模板：「我填完内容点保存，再回来发现{symptom}。」
- 禁止：接口名、状态字段名。
- 备注：说明「再回来」的操作方式（刷新/重进页面）。

### F1-ORDER-REVERT
- 触发：拖拽/排序/配置刷新后回弹。
- 模板：「我把{action}拖到最上面，刷新后就又变回原样了。」
- 禁止：存储键名、持久化实现。
- 备注：顺序类问题的标准话术。

### F1-CURVE-STALE
- 触发：参数改变但图表/曲线不更新。
- 模板：「我调了{symptom}，但曲线还是原来的样子，没有跟着变。」
- 禁止：变量名、更新函数名。
- 备注：科学可视化题常用。

### F1-ANIM-STUCK
- 触发：动画卡住/停帧/不循环。
- 模板：「动画播到一半就停住了，{symptom}，不会继续动。」
- 禁止：帧率实现、requestAnimationFrame 等 API 名。
- 备注：性能问题用 F1-SLOW；卡死用本条。

### F1-SLOW
- 触发：明显卡顿/掉帧（用户感受层面）。
- 模板：「操作起来很卡，{symptom}，感觉一卡一卡的。」
- 禁止：FPS 数值、帧时间日志（这些是 F2/L1 的事）。
- 备注：性能题 F1 只能给感受；具体指标由 L1/性能机测。

### F1-EXPORT-BROKEN
- 触发：导出文件打不开/格式不对/内容缺失。
- 模板：「我点了导出，拿到的文件{symptom}，打不开/内容不对。」
- 禁止：编码名、ffmpeg 参数、文件路径。
- 备注：说明用什么软件打开、看到什么。

### F1-INSTALL-FAIL
- 触发：App 装不上/启动即退（用户视角）。
- 模板：「我把应用装到设备上，{symptom}，打不开。」
- 禁止：包名、签名配置、hdc/xcodebuild 命令。
- 备注：装机失败的具体日志属于 F2；F3 可协助装机。

### F1-CRASH
- 触发：闪退/崩溃（用户视角）。
- 模板：「我操作到{symptom}这一步，应用直接退出了。」
- 禁止：崩溃栈、异常类型、类名。
- 备注：F2 才给 crash log。

### F1-AV-SYNC
- 触发：音画不同步/字幕错位。
- 模板：「播放到一半，{symptom}，声音和画面对不上。」
- 禁止：时间戳数值、编码参数。
- 备注：说明大致在第几秒。

### F1-WRONG-NUMBER
- 触发：结果数字/结论与预期不符（逻辑/数据/科学题）。
- 模板：「我按你的结论代回去核对，{symptom}，数字对不上。」
- 禁止：正确答案、解析解、推导提示。
- 备注：**绝不能把正确值写进 F1**；只说「对不上」。

### F1-EMPTY-NO-GUIDE
- 触发：空状态没有引导。
- 模板：「列表是空的时候，页面一片白，{symptom}，我不知道下一步该点哪里。」
- 禁止：组件名、空状态实现。
- 备注：空状态类题的标准话术。

### F1-CONTRAST
- 触发：暗色/浅色模式下看不清。
- 模板：「切到{symptom}模式后，字和背景颜色太接近，有点看不清。」
- 禁止：对比度数值（属 L1/裁判取证）。
- 备注：说明具体位置（标题/正文/按钮）。

### F1-MOBILE-LAYOUT
- 触发：窄屏/移动端布局错位。
- 模板：「我把窗口调窄之后，{symptom}，有东西叠在一起/被切掉了。」
- 禁止：视口尺寸数值（除非用户自己知道，如「手机屏幕」）。
- 备注：桌面端错位用 F1-WHITE-SCREEN 不合适，用本条。

### F1-KEYBOARD
- 触发：键盘操作无效/焦点丢失。
- 模板：「我只用键盘操作，{symptom}，按 Tab 找不到想去的地方。」
- 禁止：keydown 事件名、组件属性名。
- 备注：无障碍类题常用。

## 3. F2：日志/报错原文（12 条）

F2 = F1 内容 + 预写日志片段（逐字、已脱敏）。日志片段只能来自 defects.yaml 的 f2_evidence.text，控制器不得自由生成；禁止附根因、修复建议、代码。用到 F2 即意味着最终档位上限 D。

通用格式：「{symptom}。我这边看到一段报错，你看看：{log}」

### F2-COMPILE
- 触发：构建/编译失败。
- 模板：「{symptom}。我这边编译的时候看到：{log}」
- 禁止：解释错误原因、说改哪一行。
- 备注：{log} 为编译器错误原文（≤800 字符建议）。

### F2-RUNTIME-TRACE
- 触发：运行时异常/堆栈。
- 模板：「{symptom}。页面上弹了个错，我抄下来一段：{log}」
- 禁止：截断到只剩关键词、替模型总结错误。
- 备注：保留堆栈前 10 行即可。

### F2-CONSOLE
- 触发：控制台报错/警告升级为阻断。
- 模板：「{symptom}。控制台里有这么一段：{log}」
- 禁止：把日志改写成提示句。
- 备注：透传区间会被泄露检查掩码（仅限 LR-01/02/03/04/06）。

### F2-HTTP
- 触发：接口 4xx/5xx、超时。
- 模板：「{symptom}。我抓到一个接口返回：{log}」
- 禁止：接口实现代码、修复建议。
- 备注：{log} 可含状态码与响应体片段。

### F2-TEST-FAIL
- 触发：可见测试失败（非隐藏测试）。
- 模板：「{symptom}。我跑了一下自带的测试，输出是：{log}」
- 禁止：隐藏测试任何信息、测试文件路径（LR-07）。
- 备注：可见测试=任务说明里允许跑的测试。

### F2-STDERR
- 触发：stderr 有错误输出。
- 模板：「{symptom}。终端里打出来这些：{log}」
- 禁止：命令补全建议、参数调优建议。
- 备注：只贴原文，不加「你应该」。

### F2-EXIT-CODE
- 触发：进程退出码非 0。
- 模板：「{symptom}。最后进程退出了，退出码和输出是：{log}」
- 禁止：说「这是内存问题」之类根因。
- 备注：适合构建/服务启动失败。

### F2-DEVICE-LOG
- 触发：设备侧（鸿蒙/iOS）日志。
- 模板：「{symptom}。我从设备日志里抄了一段：{log}」
- 禁止：hdc/xcodebuild 命令（LR-06）与包名（LR-02）；命令可放在 F3 协助说明里但也不能给代码。
- 备注：{log} 由出题人从设备池采好并脱敏。

### F2-FFPROBE
- 触发：视频/音频产物格式错误。
- 模板：「{symptom}。我检查了导出的文件，信息是这样：{log}」
- 禁止：ffmpeg 参数建议、编码器选择建议。
- 备注：只列 ffprobe 事实字段。

### F2-GPU-VALIDATION
- 触发：Vulkan/Metal 验证层报错。
- 模板：「{symptom}。图形这边报了一段：{log}」
- 禁止：解释同步/布局错误的修法。
- 备注：验证层原文即可；性能问题另走 L1。

### F2-CRASH-REPORT
- 触发：崩溃报告/panic。
- 模板：「{symptom}。崩溃的时候有这样一段记录：{log}」
- 禁止：指出具体行号/函数（除非是日志原文自然包含——此时属透传，但仍禁止追加修复建议）。
- 备注：透传内容不得包含隐藏测试路径/金丝雀（LR-07/09 全级别）。

### F2-PERMISSION
- 触发：权限/签名/证书类错误。
- 模板：「{symptom}。我看了一下报错：{log}」
- 禁止：给出签名命令、证书配置步骤（属修复建议）。
- 备注：签名/装机等操作是 F3 协助，不是 F2 日志。

## 4. F3：视觉描述/协助操作（12 条）

F3 = F2 内容 + 视觉差异描述（{visual}）与/或协助操作（{assist}）。禁止给代码、补丁、根因、修复步骤。用到 F3 即意味着最终档位 D。

### F3-VISUAL-OFFSET
- 触发：元素位置错位。
- 模板：「{symptom}。我看截图里{visual}，位置明显偏了。」
- 禁止：像素坐标超出 {visual} 预写范围、CSS 属性名。
- 备注：{visual} 只描述肉眼可见差异。

### F3-VISUAL-COLOR
- 触发：颜色/对比度问题。
- 模板：「{symptom}。截图里{visual}，颜色跟我预期的不一样。」
- 禁止：十六进制色值（除非预写字段含）、调色建议。

### F3-VISUAL-MISSING
- 触发：视觉元素缺失。
- 模板：「{symptom}。我对比了两张截图，{visual}，这里应该有的东西没显示。」
- 禁止：DOM/组件名。

### F3-VISUAL-TRUNCATED
- 触发：内容被截断/溢出。
- 模板：「{symptom}。截图里{visual}，右边的字被切掉了。」
- 禁止：视口/容器尺寸实现细节。

### F3-VISUAL-OVERLAP
- 触发：元素重叠/遮挡。
- 模板：「{symptom}。截图里{visual}，两块内容叠在一起了。」
- 禁止：布局方案建议（flex/grid）。

### F3-VISUAL-SIZE
- 触发：尺寸比例不对。
- 模板：「{symptom}。截图里{visual}，大小比例看起来不对。」
- 禁止：具体像素值建议。

### F3-ASSIST-SIGN
- 触发：需要代为签名（Agent 无证书）。
- 模板：「{symptom}。签名这一步我来帮你做：{assist}，好了之后你继续。」
- 禁止：签名命令、证书路径、配置代码。
- 备注：协助操作不计修复建议；仍过泄露检查。

### F3-ASSIST-INSTALL
- 触发：需要把产物装到真机/模拟器。
- 模板：「我帮你把应用装到设备上了：{assist}。你继续看效果。」
- 禁止：hdc/xcodebuild 具体命令、包名。
- 备注：设备操作由模拟用户完成，Agent 不碰设备 shell。

### F3-ASSIST-CLICK
- 触发：需要用户点一个 Agent 无法点的系统弹窗。
- 模板：「我帮你点了那个系统弹窗：{assist}。现在应该可以继续了。」
- 禁止：解释弹窗为什么出现。

### F3-ASSIST-RESTART
- 触发：服务/进程需要重启（Agent 做不到）。
- 模板：「我帮你把服务重启了一下：{assist}。你再试试。」
- 禁止：命令原文（LR-06）。
- 备注：只描述「重启了」这个操作。

### F3-ASSIST-DEVICE
- 触发：设备掉线/需要换设备。
- 模板：「设备这边我处理了一下：{assist}。你可以继续了。」
- 禁止：设备日志原文（若要给日志，走 F2）。

### F3-ASSIST-WINDOW
- 触发：需要把窗口/分辨率调到验证尺寸。
- 模板：「我帮你把窗口调到了{assist}。你看看现在的效果。」
- 禁止：CSS 断点名、实现提示。

## 6. 模板验收

1. 每个模板的示例填充文本必须通过 [leak_rules_test.py](leak_rules_test.py)（同级别）。
2. 同一缺陷的 F1→F2→F3 升级文本必须保持「同一现象」描述，只增加信息，不改口。
3. 模板 ID 只增不改；语义变化新增 ID 并标 deprecated。
4. 每次题库新增平台，检查是否需要新模板（如设备侧、GPU 验证层）。

> 本文话术正文为「模板」；具体现象文本由题包的 rubric.f1_symptom / defects.yaml 提供，不得由模拟用户临场发挥。
