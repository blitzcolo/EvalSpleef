## 1. 目标与非目标

**目标**：规定「一道题的答案怎么造、怎么验、怎么证明验得住」：参考解、空 Agent 对照、隐藏测试、答案判定、变异测试、测试哈希锁、答案隐私与验收工作流。目标读者是出题人与验证装置维护者。

**非目标**：不规定档位换算与反馈阶梯（[03-grading](03-grading.md)）；不规定沙箱实现（[04-isolation](04-isolation.md)）；不规定榜单展示（[05](05-task-library.md)）。

**核心立场**：**答案的唯一性与隐藏测试的强度是题目的生命线**。一道题如果答案不唯一、或隐藏测试能被猜中/硬编码/改测试通过，它就不该上线——无论 rubric 写得多好。

## 2. 参考解要求

| 要求 | 具体标准 | 检查方式 |
| --- | --- | --- |
| 数量 | 每包至少 2 份（reference-a.* / reference-b.*）；复杂平台题允许 3 份 | check_repo 文件检查 |
| 思路不同 | 两份必须采用不同的核心方法（枚举 vs 约束、原生 vs 框架、单遍 vs 两遍、单 pass vs 多 pass 阴影） | 评审 + notes.md 对照表 |
| 独立实现 | 不共享关键代码（不 import 同一求解模块、不复制同一辅助函数）；可共用题面契约 | 代码 diff 评审 |
| 可执行 | 可本地执行的题必须真跑通（python3 标准库 / 系统工具链）；依赖真实工具链的题给出精确命令并标注 ≤3 处 TODO(run-on-host) | hidden-tests/run.sh + 实跑证据 |
| 通过验收 | 两份都必须通过隐藏验收（同一套测试、同一容差） | run.sh 对两份各跑一次 |
| 不泄漏 | 参考解只在验证侧；不进 Agent 镜像/工作区说明；不得被 task.yaml.resources 描述 | 工作区哈希清单 + lint |
| 说明 | notes.md 写明运行命令、关键算法、复杂度、已知限制 | 评审 |

**为什么要求「思路不同」**：验收的是一类行为而不是一份写法。若两份参考解结构相同，隐藏测试很可能只是复刻其中一份的实现细节，遇到另一种合法写法就误杀。示例：logic-001 用「穷举 320 条候选」与「同余方程约束传播」互相印证；data-001 用「pandas 向量化」与「纯 Python 流式」互相印证；web-001 用「原生 JS 状态机」与「React hooks」互相印证。

## 3. 空 Agent 对照

**定义**：空 Agent（不做任何操作、不写任何产物）跑同一 trial 流程，预期必须判 **Failed（F）**。它是「硬门槛是否真的拦截」的最低成本证明。

**流程**：第 1 轮 Agent 停止后 → 观察器执行 L1 硬门槛 → 无产物/无脚本 → 至少一个 required 硬门槛失败 → 短路，不进入 L2/L3 → tier=F，validity=valid（成绩有效，模型自身失败）。

**记录要求**（写入 answers/empty-agent.md）：
1. 操作描述（明确「零操作」）；
2. 预期结果表：每个硬门槛的 pass/fail 与理由；
3. 本地复现命令（示例包要求可直接跑出 exit != 0）；
4. 为什么该对照必要（说明该题哪一类「假通过」被它排除）。

**示例（logic-001）**：空 Agent 无 answer.json → HG1=false（ANSWER_MISSING）、HG2=false（格式违规）、HG3=true（未碰输入）→ Failed。若空 Agent 也能 P/A，说明答案比对把「没交」误判为「无缺陷」，必须修。

**反例（不允许）**：把空 Agent 写成「提交空 JSON 对象通过格式检查」；或硬门槛把「文件不存在」当成「无缺陷」。缺失必须是显式违规码，并且硬门槛失败。

## 4. 隐藏测试设计原则

| 原则 | 要求 | 反例 |
| --- | --- | --- |
| 1 与可见样例分离 | 隐藏数据/实例与 Agent 可见样例不同源（不同种子/不同文件）；隐藏测试不在工作区 | 把隐藏测试放进 starter |
| 2 防硬编码 | 参数化生成（种子在验证侧）、隐藏数据集、禁止在题面出现隐藏输入 | 题面把测试输入写死，Agent 直接 if 分支 |
| 3 确定性 | 同一输入同一结果；随机只出现在种子派生处，种子记入 trial | 依赖系统时间/网络/并发顺序 |
| 4 容差 | 数值题给绝对/相对容差与依据（如 error_rate ±1e-4、p95 ±1ms）；离散题零容差 | 用 0.01 的模糊容差放过一半错误 |
| 5 性能测量 | 性能题：预热 + 至少 5 次取中位数 + 温度/负载前置检查 + 阈值留余量 | 单次测量、冷缓存、与背景任务抢资源 |
| 6 失败信息不泄露 | 隐藏测试失败只输出机器码/比对差异，不回传期望答案全文、不回传判定公式 | 直接打印「期望答案 = ...」给 Agent |
| 7 测试哈希锁 | 隐藏测试与输入文件有 sha256 清单；被改即 invalid/作弊 | 测试可被 Agent 修改后照常通过 |
| 8 独立验证沙箱 | 测试只在验证侧执行；Agent 产物声明式导出（丢弃软链/FIFO/setuid） | 在工作区里跑测试 |
| 9 可重跑 | 测试不依赖外部网络/第三方包（可本地执行的题只用标准库）；版本锁进镜像 | 现场 pip install |
| 10 变异可证 | 每个隐藏测试至少被一个变异体覆盖（见第 5 节）；关键分支有正反用例 | 测试只断言「文件存在」 |

**测试规模基线**：逻辑题的隐藏实例数 ≥ 可见实例数；数据题的隐藏数据行数 ≥ 可见样例的 5 倍且覆盖全部脏行类别；前端题的交互用例 ≥ 8 条且覆盖「新建/移动/持久化/失败路径」；平台题至少 1 条构建/设备硬门槛 + 1 条功能回归。依据：EvalPlus 显示基础测试不足会高估正确率，需要额外测试补强（[arXiv:2305.01210](https://arxiv.org/abs/2305.01210)）。

**失败信息不泄露的具体做法**（来自本题包实践）：
- logic/data 的 checker 只返回违规码（如 RULE_MISMATCH、HOLES_MISMATCH、VALUE_MISMATCH + 字段名），自然语言 F1/F2/F3 文案由 defects.yaml/persona.md 预写；
- 比对脚本不输出完整期望值；F2 证据由验证侧生成并脱敏后交给模拟用户；
- 隐藏测试本身只在验证沙箱可读，Agent 侧不可见（[04-isolation](04-isolation.md) 第 6 节）。

## 5. 答案判定

### 5.1 通用流程

```text
产物 → 格式校验（纯 JSON/键集合/类型/范围） → 归一化 → 与唯一解比对
     → 通过：硬门槛通过；不通过：违规码 + 证据（进入 L2/L3 判定）
```

格式违规与内容错误**分开记录**：格式违规直接令硬门槛失败（题面已写明格式要求时），内容错误按 rubric 严重度计扣分；两者不得混在同一个违规码里。判定只输出 pass/fail 二值，不能输出「部分正确」作为档位依据（部分正确只进 rubric 的原子条目）。

### 5.2 逻辑题（离散答案）

| 环节 | 规则 |
| --- | --- |
| 答案抽取 | 只接受题面规定的载体（如 answer.json）；从文件解析，不做「从聊天记录里猜答案」式抽取 |
| 归一化 | 数字去前导零与空白；字符串 trim；集合去重后排序比较；大小写仅在题面声明时忽略 |
| 容差 | **零容差**（唯一解是离散对象）；数值答案若题面允许精度，按题面位数做十进制比较，禁止用浮点近似 |
| 集合比较 | 必须声明顺序语义（有序列表 / 无序集合）；无序集合先排序再比较，元素重复视为违规 |
| 格式违规 | 外层夹带说明文字、多余键、推导缺失、推导超长/含代码块、id 重复或缺漏 → 硬门槛失败 |
| 推导覆盖度 | 由 L2 裁判按 rubric 原子条目判定（是否有可核验约束、是否说明唯一性、是否只引用可见信息）；不得由脚本做自然语言判定 |
| 枚举/猜测检测 | 推导只写结论、无排除依据 → 对应 rubric fail；脚本不直接判「猜测」，避免误杀合理解法 |

**答案归一化参考实践**：Math-Verify 总结了数学答案抽取/归一化（LaTeX、集合、区间、单位）的经验，可借鉴其「先解析成结构化对象再比较」的思路（[huggingface/Math-Verify](https://github.com/huggingface/Math-Verify)）；本方案的逻辑题因答案结构固定，采用显式字段比较而非自由文本解析。

### 5.3 数据题（容差比较）

| 字段类型 | 比较方式 | 示例 |
| --- | --- | --- |
| 计数/集合/排序列表 | 精确相等（含排序键） | total_valid、malformed_by_reason、top_paths |
| 比率 | 绝对容差，容差 = 舍入位的一半 × 2 倍余量 | error_rate ±0.0001（4 位小数） |
| 分位数 | 绝对容差（毫秒），口径必须与题面一致（nearest-rank） | p95 ±1.0 ms |
| 浮点数组 | 逐元素容差 + 最大误差汇总 | 曲线/直方图 |

容差必须**写进题面**（Agent 可见），并写进 checker 常量与 task.yaml.extensions.tolerances；改容差 = 题目 MINOR 版本。容差边界必须有测试：恰好等于容差通过、超过 1 个单位失败（data-001 的 T07 即此设计）。

### 5.4 工程题（行为/视觉）

- 前端/后端：行为断言用隐藏测试（Playwright/API 测试），只断言可观察行为，不断言实现；视觉细节交 L2 裁判（截图 + 原子 rubric）。
- 平台题：硬门槛是「构建成功 + 设备/性能达标」，软标准是惯用法与结构；性能测量方法见 [04-isolation](04-isolation.md) 与各题 notes。
- 代码质量：只以可观察事实判（如「有调试输出」「测试被改」），不用主观「写得优雅」作为原子条目。
## 6. 变异测试（至少 5 个变异体必须被杀死）

**定义**：对参考解或验证装置施加小改动（变异体），若隐藏测试仍通过，说明测试没覆盖该行为（存活变异体）。变异分数 = 被杀变异体 / 变异体总数。

| 变异算子 | 示例 | 题包中的实际用例 |
| --- | --- | --- |
| 答案翻转 | next 某一位 +1、holes 删除一个 | logic-001 M1、logic-002 M1 |
| 规则替换 | perm/a/b 换成相邻候选 | logic-001 M2/M3 |
| 结构破坏 | 删除 derivation、改 id、追加重复实例 | logic-001 M4-M7 |
| 格式破坏 | 外层加说明、塞代码块、超长 | logic-001 M8-M10、logic-002 M8-M10 |
| 实现变异 | 去掉持久化、落点判定改追加、空状态永不显示 | web-001 M1-M12 |
| 口径变异 | p95 改成插值、error_rate 舍入位数变化 | data-001 M5/M6 |
| 容差边界 | 恰好等于容差 / 超过容差 | data-001 T07 双向断言 |

**要求**：
1. 每个题包 mutations.md 至少列 5 个一阶变异体（本题包实际 10-13 个），并写清「杀死它的断言」；
2. 变异体由隐藏测试在临时目录构造（不写进题包），或由人工施加后跑隐藏测试并归档结果；
3. 变异测试脚本/清单纳入哈希锁（防止「删掉变异测试就算通过」）；
4. 大于 3 个存活变异体 = 隐藏测试验收不通过（[05](05-task-library.md) 的 G5 闸门失败）；
5. 工具参考：Python 可用 mutmut 一类变异测试工具做批量扫描（[boxed/mutmut](https://github.com/boxed/mutmut)），但本题包的一阶变异体由隐藏测试自带实现（不引入依赖，符合「只用标准库」）。

**与 hidden-tests 的关系**：变异测试是**验证装置的自检**，不是对被测 Agent 的判分；其结果写入题目验收记录（第 9 节模板），不进入 trial 成绩。

## 7. 测试哈希锁与「测试自身被改」检测

**两层锁**：

| 层 | 机制 | 拦截什么 |
| --- | --- | --- |
| 包内锁 | hidden-tests/hashes.json 记录测试/生成器/输入文件的 sha256；测试启动时自校验（如 logic-001 T09） | 有人改了测试或输入期望文件 |
| 外部锁 | trial 记录写入 tests_hash（hidden-tests 目录整体哈希），与批次冻结时的登记值比较；验证容器只读挂载 | Agent 在沙箱内篡改测试；镜像/传输过程被改 |

**hashes.json 格式（建议）**：

```json
{
  "algorithm": "sha256",
  "locked_files": {
    "generator.py": "<sha256>",
    "checker.py": "<sha256>",
    "test_hidden.py": "<sha256>",
    "run.sh": "<sha256>",
    "../workspace/instances.json": "<sha256>"
  }
}
```

**检测到哈希不符时的处置**：测试装置 validity=invalid（不是模型作弊），trial 作废重跑；若差异来自 Agent 修改工作区输入文件 → 硬门槛失败并按作弊处理（error.class=cheat，disposition=zero）；两种情形用不同违规码区分（TEST_HASH_MISMATCH vs INPUT_TAMPERED）。

**为什么必须锁**：SWE-bench+ 的测量显示 31.08% 的通过补丁来自测试过弱，若测试本身可改，「通过」毫无意义（[arXiv:2410.06992](https://arxiv.org/abs/2410.06992)）。测试哈希锁把「改测试」从漏洞变成可检测事件。

## 8. 答案隐私与访问控制

| 资产 | 可见范围 | 存储位置 | 泄露追责 |
| --- | --- | --- | --- |
| 参考解（answers/reference-*） | 出题人、验证装置维护者、审计员 | 题包仓库受限目录；不进 Agent 镜像 | 泄露到公网/训练语料 → 题作废 + 追责 |
| 隐藏测试（hidden-tests/） | 同上；验证容器只读挂载 | 运行时只出现在验证沙箱 | 同上 |
| 期望答案/隐藏数据 | 验证侧（oracle/checker 可读） | 不写进 trial 可见产物 | 同上 |
| 金丝雀令牌 | harness/审计 | 生成后写入工作区与结果库 | 跨 trial 出现 → 隔离失效事件 |
| trial 轨迹与产物 | 审计、出题人；公开策略由 Lead 决定 | 对象存储（按批次保留） | 公开发布会加速题目泄露（plan 决策点） |

**访问控制要求**：
1. 仓库权限：参考解/隐藏测试目录对「出题人 + 审计」开放，被测 Agent 运行环境无任何读路径；
2. 验证侧：测试文件只读挂载；运行结束后不把 hidden-tests 拷回 Agent 沙箱；
3. 日志：验证日志不得出现期望答案全文（只留违规码与证据哈希）；
4. 泄露追责：任何外部人员/模型获取参考解即视为安全事件，按 [04-isolation](04-isolation.md) 的 runbook 处理并记录。

**答案版本与 trial 记录关联**：trial 记录必须写全 task_version、rubric_version、answer_hash（参考解/隐藏测试包哈希）、tests_hash、image_digest、model、shell 版本。重判只读旧 trial 产物 + 当前版本 checker，并把 grade 版本号写进 trial.grades[]；跨版本比较按 00-conventions 的 PATCH/MINOR/MAJOR 规则处理。

## 9. 验收工作流与记录模板

```text
出题(B1-B3) → 自检(run.sh 本地) → 参考解跑通(2 份) → 空 Agent 对照 → 变异测试(≥5 杀)
          → 哈希锁生成 → 难度标定 → 评审 checklist → 上线(active)
```

**每题验收记录模板**（写入题包 notes.md 或批次验收表；一行一题）：

| 字段 | 内容 |
| --- | --- |
| 题目 / 版本 | logic-001 / 1.0.0 |
| 验收日期 / 验收人 | 2026-11-06 / tasks-a |
| 环境 | Python 3.15.2、macOS 本机；无第三方包 |
| run.sh 结果 | exit 0，11 tests OK（证据：notes.md 第 3 节实跑输出） |
| 参考解 A / B | 均 PASS（checker hard_gate_passed=True） |
| 空 Agent | Failed（HG1/HG2=false） |
| 变异测试 | 12/12 杀死 |
| 哈希锁 | hashes.json 5 个文件一致 |
| 难度标定 | pending（目标 A-B） |
| 已知限制 | 规则族固定；m=2 记录为主 |
| 结论 | 允许上线 |

**模板对应的机读字段**：验收记录最终映射到 trial/grade 记录（[trial.schema.json](../schemas/trial.schema.json) 由 isolation 维护）与批次审计报告；不需要额外 Schema。

## 10. 各 track 验收要点

| track | 必查硬门槛 | 参考解形态 | 变异重点 |
| --- | --- | --- | --- |
| logic | 唯一解 + 答案比对 | 两份求解器（枚举/约束） | 答案翻转、规则替换、格式破坏 |
| web | Playwright 交互 + DOM 契约 | 两种前端实现 | 事件处理、持久化、主题、空状态 |
| data | 隐藏数据 + 容差 | 两种清洗实现 | 计数、口径、排序、容差边界 |
| backend | API + 压测 + 故障注入 | 两种框架/存储 | 鉴权、幂等、限流、降级 |
| debug | 隐藏回归 + 测试哈希锁 | 两种修复补丁 | 改测试、漏改、过度修改 |

## 11. 失败模式与验收标准

| 失败模式 | 表现 | 处置 |
| --- | --- | --- |
| 答案不唯一 | 两份参考解给出不同答案 / 求解器发现多解 | 题目不可上线；改规则或加约束 |
| 参考解不可跑 | 依赖缺失/环境漂移 | 锁版本；纳入 CI；≤3 处 TODO(run-on-host) 必须回填 |
| 空 Agent 通过 | 硬门槛未拦截缺失产物 | 修硬门槛；空 Agent 复测 |
| 变异存活 | 隐藏测试覆盖不足 | 补测试或降低题目复杂度 |
| 答案泄露 | 日志/产物出现期望答案 | 修 checker 输出；审计日志；重跑受影响 trial |
| 测试被改 | 哈希锁失败 | 判定装置 invalid；追查修改来源 |
| 容差过松 | 明显错误也通过 | 收紧容差；加边界测试 |
| 预算不足 | 参考解在预算内跑不完 | 调预算或拆分任务（改题 = MINOR/MAJOR） |

**验收标准（本文自身）**：参考解/空 Agent/隐藏测试/变异/哈希锁/隐私六项均有可执行规则；与 [05](05-task-library.md) 的闸门 G2-G7 对应；示例题目包按本文要求落地并实跑通过；外部引用有 URL。
