# 帮我把这个看板页面的交互补完

我们内部有个极简看板，只有一页静态文件。现在能看不能用：卡片拖不动，主题切换没反应，空列也没有提示。我列一下我想要的，你按这个做：

## 现状（起始代码在工作区）

- 三列：待办、进行中、已完成；卡片是写死的 6 张；
- 拖拽只做了一半：按住卡片会半透明，但松手不会落位、也不会保存；
- 顶部有「切换主题」按钮，点了没反应；
- 列头的卡片计数不会随移动更新；
- 每列底部有一个空状态提示，但永远不显示。

## 我要的效果

1. **拖拽排序**：卡片可以拖到同一列的另一张卡片上（插到那张卡片前面），也可以拖到别的列；拖到列内空白处就放到该列末尾。松手后立即生效。
2. **刷新不丢**：拖动结果和主题选择都要记住，刷新页面后还在。
3. **键盘也能操作**：卡片可以用 Tab 聚焦；聚焦后按右方向键移到下一列、按左方向键移到上一列、按上/下方向键在列内上移/下移。用键盘移动后同样要保存。
4. **计数**：每列列头的数字始终等于该列卡片数量。
5. **空状态**：某一列没有卡片时，显示该列底部的提示（有卡片时隐藏）。
6. **暗色模式**：点「切换主题」在浅色/暗色之间切换，整页明显变暗（背景、卡片、文字都要跟着变），并记住选择。
7. **不要引入构建步骤**：保持单页 + 静态资源，直接起静态服务器就能打开（我这边没有前端工具链）。如果你更习惯 React 等框架，可以本地构建后把静态产物放进工作区，但验收时是从静态服务器直接打开页面的。

## 硬性约定

- 不要改这些钩子：所有 `data-testid`、`data-column`、`data-card-id` 属性（验收脚本依赖它们定位元素）；卡片 id 保持 `card-1`…`card-6` 这 6 个。
- 单页里不要出现控制台报错。
- 页面在 1280×800 下三列并排可读即可，做不做移动端适配都行（但别把布局弄坏）。

## 验收方式

我会用无头浏览器实际拖卡片、按方向键、点主题按钮，并且会刷新页面复查。起始代码里的 `README.md` 也写了已知问题，可以对照。
